# 《个人品牌展示页 SEO & GEO 基础优化（1.7 版本）》

**适用对象：你本人 / 前端研发**
**目标：补齐 SEO 与 GEO 基础能力，让搜索引擎和 AI 搜索引擎能正确识别、引用和展示你的个人品牌页**

在完成了 1.6 版本的交互与视觉升级后，1.7 版本聚焦于搜索可见性基础建设。本次升级不涉及任何视觉或交互改动，纯粹为爬虫、社交分享和 AI 搜索引擎（Perplexity、ChatGPT、Claude 等）提供必要的元数据支撑。

---

# 一、改动目标与背景

## 为什么要做 SEO / GEO 优化？

- **SEO（搜索引擎优化）**：让 Google、Bing 等传统搜索引擎能正确抓取和理解页面内容，提升关键词排名和点击率。
- **GEO（生成式引擎优化）**：让 Perplexity、ChatGPT Search、Claude 等 AI 搜索引擎在回答用户问题时，能准确引用和呈现你的信息。GEO 的核心逻辑是：**给 AI 看得懂的结构化数据，而不只是对人类友好的视觉界面。**

## 本次优化范围

| 改动项 | 文件 | 说明 |
|--------|------|------|
| Canonical 标签 | `index.html` | 防止重复内容问题 |
| JSON-LD 结构化数据 | `index.html` | 核心 GEO 信号，Person Schema |
| robots.txt | `public/robots.txt` | 告知爬虫抓取策略 |
| sitemap.xml | `public/sitemap.xml` | 声明站点页面列表 |
| og-image.png | `public/og-image.png` | 社交分享预览卡片图（1200×630） |

# 二、改动详情

## 2.1 Canonical 标签

在 `index.html` `<head>` 中新增：

```html
<link rel="canonical" href="https://silencebin.com/" />
```

**作用**：明确告诉搜索引擎，本页面的权威 URL 是 `https://silencebin.com/`，避免因带参数的访问（如 `?from=wechat`）产生重复内容被降权。

---

## 2.2 JSON-LD 结构化数据（最重要的改动）

在 `index.html` `<head>` 中新增 `<script type="application/ld+json">`，使用 Schema.org 的 **Person** 类型，声明以下信息：

```json
{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Bin哥",
  "url": "https://silencebin.com",
  "email": "silence52168@gmail.com",
  "jobTitle": "AI 应用实践者 / AI 全栈落地者",
  "description": "...",
  "knowsAbout": ["AI应用落地", "AI全栈开发", "RAG知识库", "AI Agent", "AIGC", "提示词工程", "AI内容增长", "AI多模态创作", "工作流自动化"],
  "sameAs": ["GitHub", "AI 知识站点", "AI 写真站点", "AI 新闻周报"],
  "hasOfferCatalog": {
    "1对1咨询", "项目陪跑/合作", "深度合作/全职共建"
  }
}
```

**作用**：
- Google 搜索结果中有机会出现富摘要（Rich Snippet）
- AI 搜索引擎（Perplexity 等）在回答"谁是 Bin哥"类问题时，能精准引用你的职位、技能方向和合作方式
- `sameAs` 字段将多个子站点和社交账号关联到同一个实体，增强 AI 对"Bin哥"这个人物的实体识别置信度

---

## 2.3 robots.txt

新建 `public/robots.txt`：

```
User-agent: *
Allow: /

Sitemap: https://silencebin.com/sitemap.xml
```

**作用**：允许所有爬虫抓取全部页面，并主动告知 sitemap 地址，加速索引。

---

## 2.4 sitemap.xml

新建 `public/sitemap.xml`，声明首页 URL：

```xml
<url>
  <loc>https://silencebin.com/</loc>
  <lastmod>2026-05-22</lastmod>
  <changefreq>monthly</changefreq>
  <priority>1.0</priority>
</url>
```

**作用**：帮助搜索引擎发现页面，`changefreq: monthly` 适配当前内容更新节奏。

---

## 2.5 og-image.png（社交分享预览图）

在 `public/` 目录下新增 `og-image.png`（1200×630px），修复了 v1.5 版本中 Open Graph meta 标签引用的图片路径实际不存在的问题。

该图片在微信、飞书、Twitter、Telegram 等平台分享链接时自动展示，内容包含：名字、定位标语、能力标签、站点域名。

# 三、后续修改建议

以下两项是本次未完成、但对 SEO/GEO 效果影响最大的改动，建议在 1.8 版本中推进：

## 3.1 【高优先级】静态预渲染（SSG）

**问题**：当前页面是纯 React SPA，浏览器拿到的 HTML 只有 `<div id="root"></div>`，内容全部在 JS bundle 里。大部分 AI 搜索引擎不执行 JS，导致抓取到的是空页面。

**方案**：引入 `vite-ssg`，在构建时将 React 组件预渲染为完整 HTML，内容直接写入 `dist/index.html`。

**改动量**：中等，涉及 `main.tsx` 导出方式调整和 `vite.config.ts` 插件配置，需要完整测试构建产物。

**效果**：这是 GEO 效果最大的单项改进，完成后 AI 爬虫可以直接读取到完整的正文内容。

---

## 3.2 【中优先级】og-image 内容与站点内容联动

**问题**：`og-image.png` 是静态图片，未来若 tagline 或定位调整，图片不会自动更新。

**方案**：可考虑接入 `@vercel/og` 或类似服务，基于 URL 参数动态生成 og-image，或在每次内容大版本更新时手动重新截图替换。
